# Routine: Trust-Accounting and Compliance Post

Schedule: weekly, Wednesday 09:00 ET

Run the Clearing playbook "Trust-accounting and compliance post".

1. Pick this week's concept or development (for example per-owner sub-balances, commingling
   risk, a state trust-accounting requirement). For a regulation, use web search to pull the
   specifics from a Tier 2 source and record them and the date.
2. Explain the risk or rule plainly, then show how purpose-built trust accounting addresses
   it. Do not overstate the rule and do not promise legal or compliance outcomes.
3. Include the banking disclosure if funds, deposits, or insurance are mentioned.
4. If a card is used and the brand kit is locked, build it in the brand kit with a source
   credit line. If the kit is not locked, produce text only and flag the card.
5. Run the core QA gate, then the Clearing Pre-Flight.
6. Write review/trust-accounting-compliance-<date>.md (and .html if a card), Status NEEDS
   REVIEW. Log the run.

Do not publish.

---

## Clearing Pre-Flight checklist

Run after the core QA gate. All items must pass before writing to review/.

- [ ] No em dashes anywhere in the draft.
- [ ] Regulation reference traced to a Tier 1 or Tier 2 source with date recorded.
- [ ] No legal or compliance outcome promised.
- [ ] Banking disclosure present if funds, deposits, balances, or insurance are mentioned.
- [ ] Clearing is not called a bank or a property management software.
- [ ] No pricing or integration stated that is not confirmed in clearing-context.md.
- [ ] Brand kit flag present if any visual card is referenced (kit is not locked).
- [ ] Topic not repeated from the last four trust-accounting-compliance runs (check run-log.md).
